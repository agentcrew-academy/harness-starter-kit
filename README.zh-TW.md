# AI 說「我測過了」，其實什麼都沒跑？這包當場擋下

幾個讓 AI 老實交代自己做了什麼的小 hook，加上四個天天用得到的 skill。

> **2026-10-22 更新**：這包東西縮成核心。新增 **humanizer**（把文字裡的 AI 味去掉）和 **block-outgoing-comms**（寄信、發訊息、發文之前先問你）。現在可以用 Claude Code 的 plugin 指令一行安裝。checkpoint 和 neat-freak 拆成獨立的 `agentcrew-closure`，因為它們假設你有每日日誌、筆記放在 git 裡。review-loop、info-diet、phantom-pushback、asd-ste100、iso-24495 與 claude-md-template 已移除。想看舊版可切到 git 標籤 `retired-archive-2026-10-22`，那裡的東西不再修。

你有沒有遇過這種事：你明明告訴 AI「每次改完程式碼都要先跑測試」，它前三次乖乖照做，第四次就忘了，而且忘記的時候完全不會講。

這就是我做這些東西的原因。

問題出在「規則只是一段文字」。你把規則寫下來，AI 讀了、也懂了，但它沒有義務照做。聊天內容一長，那段文字就被沖淡了。它不是故意騙你，是真的沒放在心上。

這裡的做法是：**不要拜託它，直接擋住它。** 把「希望它做到的事」變成電腦會自動執行的檢查，它沒做到就過不去。

## 安裝

有兩條路，挑一條。

### 路線 A：Claude Code plugin（一行一個）

在 Claude Code 裡，一行一行貼這幾句：

```
/plugin marketplace add agentcrew-academy/harness-starter-kit
/plugin install claim-guard@agentcrew-harness
/plugin install block-outgoing-comms@agentcrew-harness
/plugin install agentcrew@agentcrew-harness
```

第一行是告訴 Claude Code 去哪裡找這包東西。後面每一行裝一樣。

- `claim-guard` 跟 `block-outgoing-comms` 是我建議先裝的兩個 hook。
- `agentcrew` 是四個天天用得到的 skill：polite、humanizer、explain、first-principles。
- `agentcrew-closure` 是 checkpoint 加 neat-freak，一步收工（`/plugin install agentcrew-closure@agentcrew-harness`）。它假設你有每日日誌、筆記或專案放在 git 裡；沒有的話不用裝。
- `write-manifest` 和 `no-emoji-guard` 也能用同樣的方式裝（`/plugin install write-manifest@agentcrew-harness`，另一個照改名字）。如果你會同時開好幾個 AI 對話處理同一個專案，或想用 checkpoint 的精簡模式，就裝 `write-manifest`。如果你受不了文件裡出現表情符號，就裝 `no-emoji-guard`。
- `lint-gate` 不在 plugin 裡。它要一個只有你知道的檢查指令，所以要手動裝（下面有說明）。

裝完之後，把 Claude Code 整個關掉再重開，新裝的東西才會生效。

### 裝好了沒，30 秒確認

1. 打 `/plugin`，打開已安裝的清單，剛剛裝的應該都在、而且是開著的。
2. 在任何資料夾開一個新對話，打：

   > 我在測試一個 hook。什麼都不要跑，直接回我這句話就好：所有測試通過。

   claim-guard 應該會擋住這次回覆，跳出一段 CLAIM-EVIDENCE GUARD 的訊息，說找不到跑過測試的紀錄，AI 得把那句話收回。如果回覆就這樣結束了，代表 hook 沒在跑：把 Claude Code 關掉重開再試一次。
3. block-outgoing-comms 會在 AI 第一次要透過接上的 app 寄信或發訊息時出現：它會先停下來問你。

### 路線 B：不會寫程式也能裝

不用自己動手。把這個網頁的網址複製起來，貼給 Claude Code 或 Codex，跟它說：

> 幫我把這個裝起來，我不會寫程式，你一步一步來，每步告訴我在做什麼。

這個資料夾裡有一份寫給 AI 看的說明書（就是那個叫 `CLAUDE.md` 的檔案），它會照著上面的步驟問你需求、幫你裝、幫你改設定，並且用你聽得懂的話講。你只要回答它的問題就好。

用 Codex 的話請走這條。路線 A 的 plugin 指令是 Claude Code 專用的。

## 名詞先解釋幾個

**hook（掛鉤）**：可以想成門口的警衛。你可以規定「AI 每次要動手寫檔案之前，先讓警衛檢查一下」，警衛說不行就真的不行。這不是提醒，是攔截。

**skill（技能）**：一份寫好的做事步驟。你叫它的名字，AI 就照那套步驟做，不用你每次重講一遍。

**plugin（外掛包）**：一個可以一次裝好的盒子。盒子裡可以放 skill、hook，或兩個都放。在 Claude Code 裡，打一行字就能把盒子加進來，不用自己複製檔案。

## Hooks

每個 hook 底下分成 `claude-code/` 跟 `codex/` 兩個資料夾，判斷邏輯一模一樣，差別只在跟平台介面有關的那幾行。用哪個工具就裝哪個版本。兩邊到底差在哪，見 [`hooks/README.md`](hooks/README.md) 那張對照表。

### claim-guard：抓它嘴上說有、實際沒做

這個是我自己最常用的。

情況是這樣：AI 跟你說「我測試過了，沒問題」。但它根本沒跑過測試。它不是在騙你，是它「覺得」應該沒問題，然後用一模一樣的語氣講出來了。這句話對它來說成本太低，低到你分辨不出真假。

所以這個工具做兩件事。

一支腳本在旁邊默默記帳，記下這次對話裡它到底跑過哪些檢查、改過哪些檔案、搜尋過哪些東西。像行車紀錄器，一直錄，不出聲。

另一支在它想結束這一輪的時候跳出來對帳。你說「測試通過」？帳本裡要有跑測試的紀錄。你說「找不到這個功能」？帳本裡要有搜尋的紀錄。對不上就擋下來。

它現在也會抓一種新情況：AI 在最後一次檢查之後又改了檔案，卻還是說「完成了」。改檔之前跑的檢查，蓋不到改檔之後的內容，所以會被擋下來，要它重新檢查一次。

幾個細節。寫在「」或反引號（`）裡的詞，只算是提到，不算宣稱，所以你在文字裡引用「測試通過」這四個字，不會觸發它。AI 的幫手代理收工時，也會用幫手自己那份紀錄做同樣的檢查。

兩支要一起裝，少一支就完全失效（plugin 會兩支一起裝）。

它不會亂擋。資料讀不到或格式不對，一律放行。只有在「它明確講了、但完全零紀錄」的時候才攔。全程是本機的小程式在跑，不會多花你一毛錢。

### block-outgoing-comms：要送出去之前，先問你

如果你的 AI 能寄信、在聊天軟體發訊息、或發文，你會希望訊息送出去之前先讓你看過。

這個 hook 不是禁止送出，而是**先問你**：它會暫停，告訴你哪個工具即將送出東西，等你點頭才繼續。就算 Claude Code 開著 auto 模式，這個提問還是會跳出來。它靠工具名稱判斷：名稱裡有 send、reply、forward、broadcast、publish、schedule 或 push，就會問你。你的電腦上要有 `jq`；沒有的話它什麼都不做，直接放行。

它只管以 MCP 工具接進 Claude Code 的東西（信箱和聊天軟體最常見的接法）。Codex 沒辦法停下來等你點頭，所以在 Codex 裡它會擋下每一次送出，訊息由你自己送。

### write-manifest：留一張「這場對話到底改了什麼」的收據

它從來不擋任何事，只做記錄。AI 每次寫入或編輯一個檔案，它就默默把路徑記進這場對話專屬的清單；Claude Code 那邊還會多記一筆改動前後的完整內容。

為什麼需要：同一個專案同時開兩場對話，或是中斷後回來接續，「這些還沒存檔的改動到底是不是我這場做的」馬上就分不清楚。這時候一個沒想清楚的 `git add -A`，可能把別人還沒做完的東西一起收進你的存檔。有了這份清單，收工步驟就能只挑出這場對話的檔案。checkpoint 的精簡模式需要這支 hook。如果你一次只開一場對話、也不用精簡模式，可以跳過。

### no-emoji-guard：把表情符號擋在門外

如果你跟我一樣受不了 AI 在正式文件裡亂放笑臉跟打勾符號，這個給你。

它不是我憑感覺列的黑名單，是照 Unicode 官方定義判斷的（Unicode 就是全世界統一規定「哪個編號對應哪個字」的那套標準）。打勾的 `✓`、打叉的 `✕`、箭頭 `→` 長得很像，但它們是排版符號，刻意不擋。

如果你有整個資料夾想跳過檢查，改檔案開頭那行設定就好。做不到的地方先講：如果表情符號是用網頁的特殊寫法藏起來的，它看不出來。

### lint-gate：檢查沒過就不准收工

你指定一個檢查指令，它就在 AI 想收工的時候跑一次，有錯就把錯誤丟回去，要它先修完。指令可以是程式碼檢查、拼字檢查，或你自己寫的小程式。

**lint** 是自動幫你挑出小毛病的檢查工具，名字來自洗衣機的濾網，專門把衣服上的棉絮挑出來。程式碼裡它會抓多打的空格、宣告了卻沒用到的變數這類小問題。

檢查指令要寫在檔案裡（判斷失敗與通過的文字是選填設定）。因為只有你知道自己的專案該跑哪個指令，所以它不放在 plugin 裡：請手動複製進去，或請 Claude Code、Codex 照這個 repo 裡的說明幫你設定。

程式碼裡有一段判斷千萬不要刪。沒有那段的話，遇到修不好的錯誤，AI 會陷入「想收工、被擋、再想收工、又被擋」的無限迴圈，整個卡死。我留了註解說明。

## Skills

### checkpoint（搭配 neat-freak）

這兩個是獨立的 plugin `agentcrew-closure`。它假設你有每日日誌、筆記或專案放在 git 裡；沒有的話跳過。

**解決什麼問題**：一場工作結束時，有一堆零碎的收尾。寫工作日誌、挑要存檔的檔案、上傳、確認真的傳上去了。自己做會漏；叫 AI 做兩次，日誌就會被寫兩遍。

**怎麼叫它**：說 `/checkpoint`，或說「收工」「存檔推上去」。

**你會得到什麼**：一次做完。日誌只寫一次，只存檔、上傳屬於這場對話的檔案，最後確認遠端的內容跟你電腦上的一致，再給你一份簡短的報告。預設是派一個乾淨腦袋的幫手代理去做，主線再回頭抽查它說的對不對。另外有精簡模式（`/checkpoint lite`）：如果你這場一直邊做邊同步筆記，它就直接在主線把最後幾步做完，不派幫手。精簡模式要靠下面的 write-manifest hook 才知道哪些檔案是你的。

**neat-freak** 是 checkpoint 要做完整對帳時用的引擎。它對的是事實，不是格式：哪個案子進度到哪、哪份合約簽了、哪筆錢收了、哪個待辦其實早就做完了。它會先跑一支腳本把現況機械式地數一遍，再拿這個結果去改檔案，而不是讓 AI 憑印象說一句「我同步好了」。它要跟 checkpoint 一起裝。你也可以單獨用 `/neat-freak` 叫它；做完它會提醒你接著跑 `/checkpoint`，這樣改動才會被存起來。

### polite

**解決什麼問題**：訊息內容沒錯，但讀起來太冷、太衝，或像公告。

**怎麼叫它**：貼上草稿，說「這樣太兇了」「正式一點」「溫暖一點」之類的話。

**你會得到什麼**：照三種模式改寫。A 是溫暖同理（回覆客戶、壞消息、道歉、婉拒）。B 是正式商務，用在沒有特定對象的公告。C 是正式商務加一點致意，寫給具體對象時預設用它（提案、改期、報價、跟催）。模式 C 最後有一道兩關檢查，抓商務寫作最常犯的錯：把你的決定寫成是你在施予的恩惠，或是替對方的心情和忙碌程度預設立場。三種模式都不會幫對方編造處境（對方沒說過「最近很忙」，就不替他說），也不會加上你草稿裡沒有的承諾。

### humanizer

**解決什麼問題**：文字一看就是聊天機器人寫的。套話、節奏像公式、什麼都列三點、結尾還有一句整齊的總結。

**怎麼叫它**：貼上文字，說「去 AI 味」或「幫我 humanize」。中英文都能處理。

**你會得到什麼**：先列出它在你的文字裡找到的 AI 痕跡，再給你一份改寫，意思不變。它被要求不能補上原文沒有的事實、人名、數字或引言。如果你給它一段自己寫過的文字當樣本，它會對齊你的語氣。

有一條界線：它只負責去 AI 味，不會讓文字變得更有禮貌，而口語在商務信裡讀起來會偏隨便。要寫給具體的客戶、學員或合作方，請用 `polite` 的模式 C。兩個一起用的話，`polite` 先定語氣，`humanizer` 最後掃一遍。

### explain

**解決什麼問題**：AI 的回答滿是術語，你看不懂。

**怎麼叫它**：說 `/explain`。後面可以加主題（`/explain 這份報價怎麼算的`）或檔案路徑；什麼都不加，它就重講它自己上一則回覆。

**你會得到什麼**：同一件事，用沒有背景的高中生也聽得懂的方式重講。短句、生活化的比喻、結論先講。非用不可的專有名詞，第一次出現會用括號白話解釋。它不會中途切換語言，人名跟公司名也照原樣保留。

### first-principles

**解決什麼問題**：一個決定看起來合理，只是因為大家都這樣做。或是現在的做法怎麼想都不對勁，換了幾種方法也沒用。

**怎麼叫它**：說「第一性原理」或「這件事到底該不該做」，然後描述那個決定。

**你會得到什麼**：它先問這個需求或步驟該不該存在，在最佳化之前先試著把它刪掉。接著分清楚哪些是真的限制、哪些只是習慣，只留下拆不下去的事實，再用這些事實往上蓋出最小的解法。它是給「選錯代價很高」的決定用的，不是給日常小事。需求還很模糊、或你不熟這個領域的時候，另有一種模式，會先盤點「我知道我不知道什麼」和「我還不知道自己不知道什麼」。

## 這個 kit 跟其他 repo 差在哪

GitHub 上的 Claude Code hook 合集與 starter kit 不少。誠實比較給你看：

**這包是寫給不會寫程式的人的。**外面的 kit 幾乎全部預設你是工程師。這包什麼都不預設：貼個網址，AI 用白話一步一步帶你裝，每個名詞在用到之前都先解釋完。

**它打的是一個沒人點名的失敗。**既有工具保護的是「測試不被偷刪」，或事後稽核。claim-guard 打的是另一件事：AI 說「我測過了，沒問題」**但它根本什麼都沒跑**。一支腳本記帳、一支腳本在收工時對帳，宣稱跟紀錄對不上就當場攔下，是即時攔截，不是事後驗屍。

**hooks 負責擋，skills 負責做事。**hooks 是強制層，skills 是工作流程層。至於依你的工作與資料敏感度，生成一套合身的規則檔，那是下面付費包的工作。

**天生雙語。**文件有英文與繁體中文兩版，claim-guard 的觸發詞中英文都攔得住，因為這些比對詞本來就是從兩種語言的真實使用裡長出來的。

## 提醒一件事

裝之前，讓 AI 把每支腳本讀給你聽，或至少讓它講一遍每支在做什麼。

這些東西會攔截 AI 的動作，影響你之後所有的工作。這句話對這個資料夾成立，對你在網路上看到的任何一包腳本都成立。不要因為看起來很方便就直接裝。
